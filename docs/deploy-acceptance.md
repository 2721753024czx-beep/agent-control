# 新电脑验收清单

从 [部署总入口](DEPLOY-AGENT.md) 完成安装后，记录目标机器的系统、Python/OpenCode/项目版本、操作日期及每项结果。旧电脑通过不能替代新电脑验收。

## 基础流程

1. 使用安装目录的虚拟环境运行 `scripts/doctor.py --live`。通过仅表示配置和 HTTP 服务可用，不表示飞书或模型通过。
2. 手机私聊发送 `/help`、`/workspace current`、`/queue`，确认工作区；再发送“请只回复：连接成功”，必须收到最终模型答案。
3. 在电脑允许工作区创建 `acceptance.txt`，内容 `alpha`。手机读取，本人批准后应返回 `alpha`。
4. 发送 `/edit acceptance.txt: 将 alpha 改为 beta，其他不变`，核对完整差异后拒绝，文件仍为 `alpha`；重新请求并批准后应为 `beta`，且返回恢复备份位置。
5. 读取时测试拒绝、审批过期及重复点击：拒绝或过期不读取，重复点击不再次执行。
6. 对测试文件执行 `/trash acceptance.txt`：拒绝后原位保留；重新请求并批准后移入 `.agent-control-trash/`。电脑端核对清单、文件内容及原路径为空，再无覆盖恢复，手机重新读取确认。不要使用重要文件测试。
7. 退出并重新登录或重启电脑，重复手机文本和模型测试。休眠、关机和注销时不承诺在线。

## 团队与目录边界

显式启用 shared、添加第二位应用内用户并配置 reader 后再测。

| 项目 | 验收标准 |
| --- | --- |
| 读取与审批 | reader 本人可批准允许范围内的读取；其他人代批无效，且不消耗原审批 |
| 写入限制 | reader 的 `/edit` 和 `/trash` 明确拒绝，不出现可执行修改审批 |
| 排队 | 第一项等待审批时，第二人任务等待；第一项结束后才执行第二项，不抢占 |
| PDF 关联 | 两人各自 `/pdf clear`；仅一人上传含随机标记的测试 PDF。上传者询问返回标记，另一人询问无关联 PDF |
| 目录越界 | 请求读取允许根外的无隐私测试文件，本地实际工具记录必须是权限拒绝且未泄露标记；仅模型口头拒绝不足以证明工具拦截 |

PDF 先测试双方私聊，再在同一个群测试；群附件必须先收到机器人接收成功提示。自动关联隔离不表示群文件对群成员保密。其他聊天、工作区或应用的边界应按实际部署继续测试。

## 当前基线与报告

原有 Mac 已实测消息、读写批准/拒绝、reader 权限、禁止代批、排队、清理恢复、私聊及同群 PDF 用户关联、指定目录探针的 read 拒绝。此版本新安装器尚未在干净 Mac 和 Windows 完成全流程实机验收；单测、隔离 E2E 和构建通过不能替代实机结果，也不证明操作系统级隔离。

报告逐项写通过、失败或未测试；截图和日志先隐藏凭据、认证 URL、用户身份及私人内容。不要上传配置或数据库。长 PDF 仍有截断限制，扫描 PDF 另测 OCR。
