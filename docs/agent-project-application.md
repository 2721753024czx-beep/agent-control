# 我与 AI 协作完成的项目｜Agent Control

我和 Codex 一起开发了 Agent Control，让我能从手机飞书给电脑上的 OpenCode 或 Codex 分派任务、审批文件操作并接收结果。我提出使用场景和权限要求，决定哪些操作需要人工确认，并负责飞书端的实机验收。Codex 根据我的反馈迭代代码、编写测试和排查故障，我们用任务记录和审计日志核对每次修改的实际效果。

系统用 Python、FastAPI 和 SQLite 实现。Hub 通过飞书长连接收消息，按设备排队。Node 领取任务，按配置选择执行引擎，并把结果回传飞书。同一台电脑上的任务串行执行，等待审批时也会保留执行位置，避免另一个 Agent 提前开始。

我把文件权限作为设计重点。Agent 读取项目文件需要一次性审批，审批绑定发起人和任务。单文件修改由 AI 生成草案，Node 将完整差异发到飞书，发起人批准后才备份并写入。只读成员不能编辑。PDF 在本机提取文本，后续任务按用户、聊天和工作区关联附件，避免同群不同用户的任务自动引用对方上传的文件。

一次手机端回归中，Codex 桌面更新替换了内置 CLI，后台因版本校验停止执行。我和 AI 先用隔离测试验证新版，再将经过验证的 CLI、签名应用包和辅助程序保存为独立运行时，使桌面更新不再替换后台版本。我们用真实飞书账号在 Mac 上验收了读写审批、代批拦截、跨引擎排队、PDF 关联隔离及 Node 重启恢复。公开仓库保留源码、测试和部署说明。
